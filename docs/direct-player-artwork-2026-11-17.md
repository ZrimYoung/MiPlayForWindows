# 播放器高清封面直接来源核验（2026-11-17）

本轮为只读可行性核验，没有修改运行中的 0.5.10、播放器状态或手机设置。

## Apple Music

- 当前 Apple Music 曲目的 MediaRemote store ID 与 Music 脚本曲目快照核对通过。按精确 ID 查 Music 自身只读响应缓存，同时核对标题、歌手、专辑及时间；不按歌名搜索或使用其他平台匹配。
- 匹配响应提供 artwork 地址模板和 4000×4000 尺寸。只读取响应正文，不读取请求 Cookie、账号凭据或授权头。
- 地址模板使用 {w}/{h}/{c}/{f}，本轮使用 bb 裁剪参数及 JPEG 输出，仅访问 HTTPS 的 mzstatic.com 图片子域。重定向同样受域名限制；响应不超过 8 MiB。
- 实际请求 2048×2048 版本：解码为 JPEG，817746 字节。
- 实际请求元数据标注的 4000×4000 版本：解码为 JPEG，2277711 字节；请求结束后再次核对，仍是同一个活动歌曲 ID。
- 原图只在内存中检查，没有保存图片或歌词正文。这证明该曲目可取得比系统缩略图更大的官方封面，不代表取得母版文件，也不保证所有曲目具有相同尺寸。
- 0.5.10 尚未接入；0.5.11 新增默认关闭的「主动获取 Apple Music 高清封面」开关。启用后以系统封面即时占位，后台获取精确曲目高清图，核对曲目未变化后替换，再执行现有格式/尺寸/大小上限。网络失败或缺缓存时保留系统封面，不阻塞音频，不猜测匹配。

## QQ 音乐

- 本轮只读访问自身容器缓存仍返回 PermissionError；没有绕过或更改系统权限。
- 尚未验证可可靠关联当前曲目的专辑 ID 或原始封面地址，不能把系统队列标识当作 QQ 曲目/专辑 ID。
- 本轮没有使用歌名搜索兜底，没有接入 QQ 高清封面获取。

## 0.5.11 实现边界

- 与歌词开关独立，封面查询不读取歌词。只允许已核对的 Apple Music 当前曲目精确 catalogue ID，下载前后均复核。
- 仅读取 Music 自身缓存的曲目正文及官方 HTTPS 图片地址；请求 2048 最长边版本，内存响应上限 8 MiB，无 Cookie/凭据。失败使用系统图，20 秒退避重试。
- 开启后先显示系统图，高清图下载、解码、按设置压缩均在后台；关闭立即取消读取并恢复系统图。切歌、来源改变、退出播放器后旧回调不能覆盖新曲目。当前曲目图片只在内存保存。
- 接收端实际尺寸仍受封面大小上限及质量设置影响。高清来源尺寸与发送尺寸分别显示，不把缩略图放大称作高清。
- 发送端标题审计：系统 `title` → 原生 `item.title` → IPC `title` → `MiPlayMediaSnapshot.Title` → 协议 `mTitle`；歌词独立进入 `mLrc`（UTF-8 Base64）。没有按歌词进度替换标题的逻辑。上游播放器自行更改系统标题、接收端自行展示歌词为标题不在该保证范围；不添加无实际作用的标题开关。
